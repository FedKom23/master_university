### Часть 1: MLFLow (2 балла)

#### Задание
В рамках задания необходимо обучить модель в MLFLow для нашего соревнования  [Production ML Spring 2026](https://www.kaggle.com/t/ade5bc7b22a94c1bae68ae4392b974fb)


Работу необходимо выполнить на основе базового docker compose,  
который находится по пути:

```code
./mlflow_docker/compose.yml
```

Создайте в вашем бакете на S3 prefix(путь) - например, _mlflow_

Создайте эксперимент в MLFLow с **минимум тремя запусками (runs)**.
Каждый запуск должен содержать:

**1. Логирование модели**

Сохраните обученную модель как артефакт в MLflow

**2. Логирование метрик качества в артефакты**

Разделите датасет на _train_ и _test_, посчитайте метрики:

* `train_accuracy`
* `test_accuracy`
* `train_f1_macro`
* `test_f1_macro`

Сохраните их в файл `classification_metrics.json`:
Пример:
```json
{
  "train_accuracy": 0.95,
  "test_accuracy": 0.87,
  "train_f1_macro": 0.93,
  "test_f1_macro": 0.85
}
```

Залогируйте этот файл как артефакт.

**3. Логирование распределения классов**

Посчитайте распределение целевых меток (`category_ind`) в датасете
`train.parquet.snappy` и сохраните в `dataset_label_counts.json`

В файле каждая пара ключ: значение имеет вид

- ключ (строка) — метка класса (category_ind),
- значение (целое число) — количество встречаемости этой категории в датасете.

Пример:
```json
{
  "34": 31563,
  "71": 4616,
  ...
}
```

Также залогируйте как артефакт.

---

**Структура артефактов**

Для модели:
```
s3://{bucket_name}/{prefix}/{experiment_id}/
│
├── models/
│   └── m-.../
│       └── artifacts/
│           ├── MLmodel
│           ├── ...
│           └── ...
```
Для файлов:
```
s3://{bucket_name}/{prefix}/{experiment_id}/
│
├── {run_id}/
│   └── artifacts/
│       ├── classification_metrics.json
│       ├── dataset_label_counts.json
│       └── ...
```

### Что на выходе
Измените файл **`config.toml`**, заполнив секцию:
```toml
[[mlflow]]
s3_path = "<username>/<prefix>"
experiment_id = "<your_experiment_id>"
```

## Часть 3: Интерфейс Label Studio (1.5 балла)

На предыдущих шагах вы обучали модель на готовых фичах.
Однако в реальных проектах часто возникает необходимость добавлять новые признаки, чтобы улучшить качество модели.
Давайте добавим в разметку поле **цена товара**, которое в будущем может использоваться как дополнительная фича для обучения модели.

---

### Задание

1. Откройте файл **`labeling_interface.xml`** (уже лежит в репозитории).
2. Найдите участки с пометками `<!-- TODO: ... -->`.
   Вам нужно **дополнить XML-шаблон в этих местах**, чтобы интерфейс стал полностью рабочим.
3. В комментариях под каждым `TODO` уже подробно указано,
   **какой тег нужно добавить и какие атрибуты задать** — следуйте этим подсказкам. 
---

### Что на выходе
Измените файл **`labeling_interface.xml`**, удалив все TODO и добавив недостающие элементы согласно комментариям.
