## Как сдавать решение и в какой срок

### Оценка
За задание можно получить 5 баллов, если сдать до Soft Deadline. После него, но до Hard Deadline -- половина баллов. После решение не оценивается.

### Дедлайны
**Soft Deadline - 5 марта в 23:59.**

**Hard Deadline - 12 марта в 23:59.**

### Формат сдачи
1. Нужно завести ветку `hw2` и вести свою разработку там.
2. Вам доступны для добавления, изменения файлы `pyproject.toml`, `uv.lock`, `.python-version`, `Dockerfile`, `compose.yaml`.
3. Локально тесты можете запускать так (из директории `hw2`, также нужно добавить в проект пакеты `pytest` и `pytest-dependency`):
   ```
   uv run python -m pytest --log-cli-level INFO .
   ```
4. Как только считаете, что решение готово, заводите Merge Request из ветки `hw2` в `master`.
5. Если с прошлым МР-ом что-то было не так и вы решили завести новый, закройте, пожалуйста, старый самостоятельно. Это делается на странице МР-а: Троеточие -> Close merge request.
6. Если пайплайн полностью проходит (все зеленное), бот отписал комментарий с баллами в ваш MR, ставьте в assignee `Владислав Ефимов`.
7. Profit!

## Задания
### 1. Фиксация зависимостей с помощью uv (1 балл)
Инициализируйте uv проект в директории с ДЗ.

Изучите тестовое приложение `app.py`, сформируйте список зависимостей, зафиксируйте их с помощью uv. Добавьте файлы с зависимостями в git.

### 2. Dockerfile
Создайте `Dockerfile`, в котором будет запускаться тестовый сервис:
1. В качестве базового образа возмите `ghcr.io/astral-sh/uv:python3.12-bookworm`.
2. Рабочая дирекория приложения должна находиться в `/app`.
3. Запуск сервиса должен происходить из под пользователя `appuser`.
4. Подтяните зависимости через uv, используя файлы с ними из задания 1.
5. При запуске контейнера должен запускать и тестовый сервис:
    ```
    uv run python app.py
    ```

### 3. Docker compose
Создайте compose файл с тремя сервисами:
1. app -- сервис с нашим тестовым приложением.
2. db -- сервис с базой данных Postgress, можно взять в качестве бащового образа `postgres:15`.
3. extra -- контейнер заглушка, можете взять за основу образ `alpine`, а в качестве команды `sleep infinity`.

Требования:
1. Наш тестовый сервис `app` должен иметь сетевой доступ до `db`.
2. Контейнер `extra` не должен иметь сетевого доступа до `db`.
3. Доступ до приложения должен быть через специальный порт, который указан в переменной окружения `$TEST`.

### 4. Gitlab registry
1. Выпишите себе токен для работы с режистри (права `read_registry`, `write_registry`).
2. Авторизуйте docker локально с помощью него: `docker login` + имя токена в качестве логина + значение токена в качестве пароля.
3. Соберите ваш образ из задания 2 с помощью `docker build`.
4. В качестве тега возмите путь своего репозитория + `/hw2`. Например:
    ```
    registry.gitlab.v-efimov.tech/production-ml-spring-2026/homeworks/your_username/hw2
    ```
5. Загрузите полученный тэг в режистри с помощью `docker push -t`.
