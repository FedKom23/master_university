## Задача

### Мотивация
В реальных датасетах часто встречается сильный дисбаланс категорий.
Например, в тренировочных данных нашего соревнования [Production ML Spring 2026](https://www.kaggle.com/t/ade5bc7b22a94c1bae68ae4392b974fb) категория "наушники и аксессуары" составляет всего **0.04%** от общего объема.
В реальной практике мы бы могли извлечь информацию из специализированных доменов, чтобы дообогатить датасет и улучшить качество ML-модели.

---

### Описание

В этом задании вам предстоит реализовать парсер, который извлекает информацию о товаре с HTML-страницы интернет-магазина.  
Страницы имитируют карточки товаров наушников. Для домашнего задания было сгенерировано пять таких страниц.

Вам доступны первые два товара: `product1.html` и `product2.html` (находятся в папке `domain_headphones`).  
Остальные три страницы скрыты и будут использоваться при автоматическом тестировании.  

Все страницы имеют похожую структуру, что часто отражает особенности реальных сайтов одного домена.  
Гарантируется, что для всех страниц можно написать один универсальный парсер, который корректно извлечёт необходимые данные.

### Оценивание

- За каждый верно найденный атрибут начисляется **0.25 балла**.  
- Максимальный балл: **5.0** (0.25 x 4 атрибута x 5 товаров).

Для решения задания можно использовать следующие библиотеки:

- `requests`  
- `playwright` (в headless режиме, браузер Chromium)  
- `BeautifulSoup`  
- `lxml`

Для проверки работы функции можно поднять локальный HTTP-сервер:

```bash
python -m http.server 8123
```

После этого страницы будут доступны по адресам:
- http://localhost:8123/domain_headphones/product1.html
- http://localhost:8123/domain_headphones/product2.html

### Особенности автопроверки при использовании Playwright

Все нужные атрибуты продукта (`title`, `vendor`, `description`, `price`) уже доступны в HTML, без необходимости взаимодействовать с динамическими элементами (popup, анимации, lazy-load и т.д.).  

Если используете Playwright, работайте с HTML *как со статической страницей*: извлекайте текст элементов напрямую, игнорируя popup и анимации.  

Так код стабильно проходит автопроверку и остаётся удобным для локальной отладки.
